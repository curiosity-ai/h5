# H5.Translator.Roslyn — Port Plan

## 1. Goal

Create a **new, independent** C#-to-JavaScript translator, `H5.Translator.Roslyn`, that:

- Uses **Roslyn only** (`Microsoft.CodeAnalysis.CSharp`) for compiling and parsing C#.
- Iterates the Roslyn **syntax tree** (guided by the **semantic model**) and emits JavaScript directly.
- Contains **no rewriter pass** and **no `ICSharpCode.NRefactory.CSharp`** dependency.
- Targets **C# Latest**.
- Reports language features that do not make sense in a browser (pointers, `unsafe`, `stackalloc`, `[DllImport]`, threading/synchronization primitives, file I/O, etc.) as **compilation errors**.

The existing compiler (`H5/Compiler/Translator`, `SharpSixRewriter`, NRefactory) is **not modified**. All work lives in new project(s).

## 2. Why a clean-room design

The legacy pipeline is: NRefactory parse → `SharpSixRewriter` (Roslyn) lowers modern C# into old C# → NRefactory AST → `Emitter` blocks → JS. It carries two front-ends and a lowering pass whose only purpose is to make new C# look like C# 5.

Roslyn already gives us:

- A full parser and **semantic model** (symbol resolution, overload resolution, conversions, constant folding, nullability, flow analysis).
- Built-in knowledge of **every** language version, so "target Latest" is free — new syntax parses without a rewriter.

So the port collapses three stages into one: **`SyntaxNode` + `SemanticModel` → JS**. Lowering that the legacy path did by rewriting source (e.g. `record` → `class`, pattern `switch` → if/else, deconstruction → temp locals) is done here directly in the emitter, node by node.

## 3. Architecture

```
H5.Translator.Roslyn/
├── H5.Translator.Roslyn.csproj      # net10.0, LangVersion=latest, Roslyn 5.3.0
├── Compilation/
│   ├── RoslynTranslator.cs          # public entry point: source(s) -> JS + diagnostics
│   ├── CompilationBuilder.cs        # builds CSharpCompilation, references, parse options
│   └── TranslationResult.cs         # { Javascript, Diagnostics, Success }
├── Support/
│   ├── UnsupportedFeatureScanner.cs # walks trees, raises errors for browser-incompatible constructs
│   ├── TranslationException.cs
│   └── NameMangler.cs               # C# name -> safe JS name, overload disambiguation
├── Emit/
│   ├── JsWriter.cs                  # indentation-aware string builder
│   ├── Emitter.cs                   # orchestrates: emits assembly IIFE, types, bootstrap
│   ├── TypeEmitter.cs               # class/struct/interface/enum/delegate
│   ├── MemberEmitter.cs             # fields, properties, methods, ctors, events, indexers
│   ├── StatementEmitter.cs          # all StatementSyntax
│   ├── ExpressionEmitter.cs         # all ExpressionSyntax
│   ├── PatternEmitter.cs            # is-patterns, switch expressions/statements
│   └── ConversionEmitter.cs         # implicit/explicit conversions, boxing, numeric coercion
└── Runtime/
    └── h5roslyn.runtime.js          # embedded minimal JS runtime (BCL surface)
```

### 3.1 Front-end (Roslyn)

`CompilationBuilder` creates a `CSharpCompilation` with:

- `LanguageVersion.Latest`, `OutputKind.ConsoleApplication`.
- Reference assemblies for the target reference set (the .NET ref pack the host resolves), so the semantic model binds `System.*`.
- A `SemanticModel` per syntax tree.

Roslyn diagnostics of severity `Error` abort translation and are surfaced to the caller. This gives us **free** and **correct** validation of the C# before we emit a single character.

### 3.2 Unsupported-feature policy

`UnsupportedFeatureScanner` runs after a clean compile and before emit. It walks every tree and reports a `TranslationException`/diagnostic (`H5R####`) for constructs that cannot run in a browser:

| Feature | Detection | Message |
|---|---|---|
| Pointers (`int*`, `&x`, `*p`) | `PointerTypeSyntax`, `PrefixUnaryExpression` `&`/`*` | `Pointers are not supported` |
| `unsafe` blocks/members | `UnsafeStatementSyntax`, `unsafe` modifier | `Unsafe code is not supported` |
| `fixed` statements / fixed buffers | `FixedStatementSyntax`, `FixedSizeBufferDeclaration` | `Unsafe code is not supported` |
| `stackalloc` | `StackAllocArrayCreationExpressionSyntax` | `stackalloc is not supported` |
| `[DllImport]` / `extern` | attribute / modifier | `Native interop is not supported` |
| Threads, locks, `Monitor`, `Mutex`, `volatile` | symbol namespace / modifier | `Threading primitives are not supported` |
| File / socket I/O (`System.IO`, `System.Net.Sockets`) | bound symbol namespace | `<API> is not supported in the browser` |

The policy is **deny-by-namespace/symbol** for the runtime BCL (only the modeled surface is allowed) plus **deny-by-syntax** for the language constructs above. Anything unmodeled reports a clear "not supported" error at compile time rather than producing broken JS.

### 3.3 Emit target

- **Modern JavaScript (ES2020+)** — evaluated in Chromium via Playwright, matching the existing test harness.
- The emitted assembly is wrapped in an IIFE. Types are registered on a global namespace tree (`var App = App || {}` style). No dependency on the legacy `h5.js` runtime — a **small self-contained runtime** (`h5roslyn.runtime.js`) is prepended.
- `async`/`await` map to native JS `async`/`await` + `Promise`; `Task`/`Task<T>` map to `Promise`.
- The entry point (`Main`) is invoked at the end of the bundle so Playwright captures its `Console` output.

### 3.4 Runtime (`h5roslyn.runtime.js`)

Deliberately minimal and grown feature-by-feature. Initial surface:

- `System.Console.WriteLine/Write` with .NET-style formatting (composite format strings, `{0}`).
- Numeric helpers: integer division/overflow truncation (`(a/b)|0`), `.NET` `double`/`int` `ToString`.
- `System.String` members used by tests (`Format`, `Concat`, `Substring`, `Length`, `Replace`, …).
- Equality/`ToString`/`GetHashCode` dispatch, `Nullable<T>`, boxing.
- Collections (`List<T>`, `Dictionary<K,V>`, arrays) and LINQ-to-objects — added when their feature phase lands.

Matching .NET `Console` output exactly is the correctness bar (tests diff against native Roslyn execution), so formatting fidelity is prioritized over breadth.

## 4. Feature-by-feature roadmap

Each phase = a vertical slice with mirrored integration tests (`H5.Translator.Roslyn.Tests`) that diff JS output against native Roslyn output, exactly like the existing suite.

> **Status (living):** Phases 0–7 are implemented with mirrored tests passing (diffed vs native
> .NET). Covered: OOP, generics, collections, LINQ, iterators, patterns, tuples, records,
> async/await, struct value-copy semantics, and a broad BCL surface
> (`Console`/`String`/`StringBuilder`/`Math`/`Convert`/`Random` (deterministic, matches .NET)/
> `DateTime`/`TimeSpan`/`Guid`/`Nullable<T>`), user-defined operator overloading, LINQ **query
> syntax** (from/where/orderby/select/group by), and DateTime/TimeSpan arithmetic operators.
> Interfaces are runtime-tracked (so `is`/patterns against them work) and anonymous types are
> supported. Remaining/known gaps: `is int` vs `is double` on boxed numbers (best-effort via
> `Number.isInteger`), query `let`/`join`/multi-`from` (use method syntax — `into` is supported),
> deterministic `using`-declaration disposal, `goto`, `++`/`--` operator overloads, and `Decimal`
> precision (mapped to JS number).

### Phase 0 — Infrastructure ✅
- Project scaffold, `CompilationBuilder`, diagnostics surfacing, `UnsupportedFeatureScanner`, `JsWriter`, emitter skeleton, runtime bootstrap, entry-point invocation, test harness.

### Phase 1 — Basics ✅
- Classes with static `Main`; `Console.WriteLine`/`Write`.
- Local variables (`var`, explicit), literals (int, long, double, bool, char, string, null).
- Arithmetic / relational / logical / bitwise operators, integer-division semantics, unary ops.
- `if/else`, `for`, `while`, `do/while`, `break`, `continue`, `return`.
- String concatenation and interpolation.

### Phase 2 — OOP ✅
- Instance fields, auto-properties + full properties, methods, constructors (incl. `this`/`base` chaining), static members and static ctors.
- Inheritance, `virtual`/`override`/`abstract`/`sealed`, `base.` calls.
- Interfaces + explicit implementation, default interface members.
- Overload resolution → JS name mangling.
- `enum` (incl. `[Flags]`, explicit values), `struct` value semantics (copy on assignment), `delegate` + multicast, events.

### Phase 3 — Generics & collections ✅
- Generic classes/methods, constraints, type inference.
- Arrays (1-D, jagged, multi-dim), `foreach`.
- `List<T>`, `Dictionary<K,V>`, `HashSet<T>`, `IEnumerable<T>` iteration.

### Phase 4 — Functional & LINQ ✅
- Lambdas, `Func`/`Action`, closures, local functions.
- Iterators (`yield return`/`yield break`) → generator functions.
- LINQ query + method syntax (Where/Select/OrderBy/GroupBy/Aggregate/…).
- Extension methods, named/optional arguments.

### Phase 5 — Error handling & async ✅
- `try/catch/finally`, `throw`, exception filters, `using`/`using` declarations, `lock` → no-op-with-body (or reported), `checked/unchecked`.
- `async`/`await`, `Task`/`Task<T>` → `Promise`; `ValueTask`.

### Phase 6 — Modern C# (7 → Latest) ✅
- Tuples + deconstruction, pattern matching (`is`, `switch` expression, relational/list patterns), `out var`, ref locals where expressible.
- `record`/`record struct` (value equality, `with`), init-only setters, target-typed `new`, top-level statements, primary constructors, collection expressions, `nameof`, string interpolation handlers, raw string literals, `required` members, `field` keyword.
- Nullable reference types (erased at emit; used only for analysis).

### Phase 7 — Standard library breadth 🔶 (in progress)
- `Math`/`MathF`, `Convert`, `DateTime`/`TimeSpan`, `Random`, `StringBuilder`, `Guid`, `Nullable<T>` operations, `BitConverter`, formatting/`IFormattable`.

Features reached but judged browser-incompatible are reported per §3.2 rather than emitted.

## 5. Testing strategy

- `Tests/H5.Translator.Roslyn.Tests/` mirrors `H5.Compiler.IntegrationTests`:
  - `RoslynNativeRunner` compiles + runs the C# with `Microsoft.CodeAnalysis.CSharp.Scripting`/in-memory emit for the "expected" output.
  - `RoslynTranslator` produces JS; `PlaywrightRunner` runs it headless; outputs are normalized and diffed.
  - `RunTestExpectingError` asserts unsupported-feature diagnostics.
- Tests are **ported** from the existing suite (same C# snippets) so behavior parity is directly comparable — the existing tests are not modified.

## 6. Non-goals / explicit exclusions

- Reflection metadata emission, source maps, minification, module/AMD output, TypeScript `.d.ts` — out of scope for the initial port (can be layered later).
- Byte-for-byte parity with the legacy emitter's JS. The bar is **behavioral** parity (identical `Console` output vs. native Roslyn), not identical source.
